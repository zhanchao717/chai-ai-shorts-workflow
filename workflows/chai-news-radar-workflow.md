# 柴主编新闻雷达 V2.2

版本：2026-10-01。用于发现重要热点和观众影响，输出线索与编辑候选；不自动写稿或发布。

## 三层输入

1. **原始材料**：公司公告、研究团队博客、论文、正式发行记录、原始访谈或可复现测试。公告可以证明公司说了什么，不能单独证明宣传效果。
2. **中文媒体**：新智元、量子位为主要发现入口；机器之心、智东西、AI科技评论补充论文、行业与采访。媒体独家/实测可成为特定断言的原始材料，须检查作者、条件与是否有完整记录。
3. **观众问题**：本账号评论、单条作品数据、同类内容评论。热度只帮助发现，最终判断是普通观众能做什么决定。

已验证的入口、采集方式和覆盖缺口在 `chai-news-radar-sources.json`。采集失败、空页、人工入口分别记录，不能用旧缓存冒充新抓取成功；官网同步不等于公众号原生时间或完整推送。

## 每次运行

```bash
bash scripts/daily_topics.sh --hours 48 --limit 12
# 需要即时重读时：
python3 scripts/chai_news_radar.py --refresh
# 只深读一条，并提取可能的一手链接：
python3 scripts/chai_news_radar.py --inspect-url <媒体文章URL>
```

默认 JSON/简报留 `/tmp`，原始缓存留 `~/.agent-reach/chai-news-radar`。需要留存某轮可显式指定 `--json`、`--report` 路径。默认 10 分钟内复用同一 URL 的抓取，不调用大模型；`--refresh` 强制重读。脚本本身不会创建定时任务。

1. 先看信源健康、最后实际读取时间与缓存标记。时间窗口过滤按带时区的真实发布日期，未知时间另队列；未来时间剔除并记录异常。
2. 简报最多 12 条、每入口最多 3 条；全量短字段留 JSON。时间排序不叫“价值排序”，来源频繁更新不自动更值得做。
3. 只深读最相关的 3 条，核对媒体引用的公告、论文或实测。记录 `media_published_at`、`event_published_at`、`first_seen_at`、`verified_at`。时区/时间未知标未知；不得凭“刚刚”或首页置顶推断今天发生。
4. 按**同一官方原文 URL + 同一事件/版本 + 同一观众任务**合并多篇报道。新雷达自动去除同 URL，保留其他入口；跨不同媒体 URL 的事件合并由编辑填原始事件键，不能用相似标题误合并。
5. 对照已发布作品和本轮被否决候选。新版本、开放地区、费用、任务结果有实质变化才做跟进；不得把被拒的旧选题换标题再推回来。
6. 填四项必答、证据画面、受众影响后，按主流程评分。纯融资、排行榜、明星言论、未经验证的重大宣称可留观察，不因标题刺激而拍。

## 交给编导的三条卡片

每张卡只给：事件与原文、时间、受影响的人、一个可见变化、现在能做的决定、可拍证据、尚未验证项，以及与上一期区别。写在 `editorial-brief.md`；价钱、开放资格、性能等重要断言逐条核对后才标“已核验”。没有证据，写“待核验”，不自动换成肯定句。

## 原生公众号补充

可将用户手动分享的公众号链接接入同一链路；微信公众号独家内容不能保证在官网出现。WeRSS 是候选补充方案，需另行部署、授权账号并验证同步；当前未接入。WeWe RSS 上游已归档，不作为新主链默认依赖。工具研究见 `docs/AI公众号与一手信源调研-2026-10-01.md`。

## 本轮完成与边界

已经实现：公开入口并行读取、短字段输出、缓存复用、真实时间过滤、源健康记录、URL 去重、来源配额与原文链接提取。

尚未实现：原生公众号完整覆盖、跨进程状态锁、跨 URL 自动事件聚合、自动事实核验、自动编辑评分。`seen_before` 仅表示抓过，不表示已审或已制作。采集节省重复网络读取；token 节省与选题质量仍须用实际任务测量。
