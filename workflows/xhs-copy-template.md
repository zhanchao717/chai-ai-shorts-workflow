# 小红书文案契约 V2.1

版本：2026-10-01
门禁：`python3 scripts/chai_xhs_copy_check.py <publish-copy.md>`。

EP.226 曾观察到三平台文案高度重复。这是编辑质量问题，尚无证据证明它是涨粉停滞的原因。小红书按观众的扫读、搜索与保存需求独立写，标题既可帮助搜索，也可表达值得点开的具体问题。

## 阻断项

- 缺标题或正文。
- 标题超过本账号保守预算 20 字；正文超过 1000 字。最终以发布页实际计数、规则和提示复核，这些不是对平台永久规则的承诺。
- 公开正文含网页链接。用户 2026-10-03 更新：公开正文不附来源段、材料清单或核验日期；材料与 URL 留内部 `sources.md`。
- 与另一平台标题及正文的二元组相似度 ≥90%：回编辑复核并重写。此指标只用于找重复，不能判断原创性或预测流量。

## 编辑提示（不阻断）

默认正文可从 200–420 字起草；标题短长、首句长度、长行、空行和标签数量给提示，由内容决定。**不规定 emoji 数量，不强制问句或关注口号，不为过检查凑字。**品牌名、关键产品名能帮助理解就保留；不使用无事实支撑的悬念。

推荐写法按题材选：

- 公告解读：观众现在最想知道的答案 → 官方事实与开放对象 → 对观众的影响 → 可执行判断及不确定项。
- 教程：结果 → 亲测步骤/可复制内容 → 设备、版本与限制。
- 对比：同一任务与条件 → 可复算差异 → 谁适合/谁不适合。

每段只承担一件事；手机首屏能看见价值。可用 emoji 作视觉锚点，也可用自然分段。正文提供视频之外的清单或判断标准，避免只是抄口播。事实表述明确区分公司自述、实际测试与编辑建议；公开正文不附来源段。

标签先选准确产品/事件名，再选正文实际回答的场景或功能；一般从 2–4 个相关标签起草，不凑数量。发布页核对可选话题，不把未核对的标签称为热门。具体原则以端到端流程 2026-10-03 更新为准。

文件格式沿用：`## 小红书` 下含 `**标题**`、`**正文**`、`**话题**`；公开文案只写最终选定标题。

❌ 必须修复；⚠ 由编辑判断。检查通过后仍需审查事实、承诺和实际发布页面。
