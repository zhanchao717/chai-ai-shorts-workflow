# 了不起的小超人｜行业 × AI 工作流（2026-08-17 起由「开源装备雷达」改版）

## 定位与启动

这是按行业挂钩的开源工具栏目：仍然每天从 GitHub 热榜抓工具，但**每个工具绑定一个真实行业场景**讲。观众因为「这说的是我的行业」停下来，AI/工具只出现在「怎么做到」那一步。

> 改版原因（2026-08-17）：原「开源装备雷达」受众太窄（开发者/技术圈），「普通人 AI 小贴士」没人看。用户拍板：保留 GitHub 热榜更新节奏，改为「行业 × AI」——先打**电商/带货 + 开店实体**，人设仍是黄色 IP 头像「了不起的小超人」，视觉系统不变。

自动化每天按 Asia/Shanghai 在 07:30 和 17:30 各启动一次。每次重新检查热点和增长信号，并与过去 30 天及当天早一轮内容去重；每轮最多生产 3 条，低于质量线时宁缺毋滥。

## 每轮生产流程

1. 用 **agent-reach** 的 GitHub 通道调研（`agent-reach doctor` 确认可用；命令即 gh CLI：`gh search repos "<query>" --sort stars`、`gh api repos/<owner>/<repo>`、`gh api .../readme`）。开始前先声明「使用 agent-reach 的 GitHub 后端」。收集 GitHub Trending、Star 增速、项目官网和开发者讨论，最多 18 个候选。
2. **行业匹配门（新增，必过）**：这个工具能不能在【某个真实行业】里解决一件具体烦人事？能 → 立项；只能给程序员用 → 跳过。
3. 核验官方仓库、创建或更新时间、许可证、README、演示、硬件与账号门槛，以及中国大陆用户是否有实际使用路径。
4. 按视觉结果、用户价值、新鲜度与增长、新手成本、维护质量评分；低于 70 分不制作。
5. 每条只服务 1 个行业 + 1 个工具；优先从已锁定行业（电商/带货、开店实体）里选题，可逐步扩行业。
6. 为每个入选主题建立独立工程：`content/YYYY-MM-DD/xiaochao-NNN-slug/`。期号从现有小超人内容顺延，禁止覆盖旧目录。
7. 完成口播、抖音与小红书文案后，使用 DBS 工具检查开头、共鸣、AI 味和标题；修复实质问题后再配音。
8. 用 MiniMax 生成分段口播，按真实音频时长编排 HyperFrames 画面和逐句字幕。
9. 运行 HyperFrames check、快照和代表帧检查；渲染 1080×1920、30fps、H.264/AAC 成片。
10. 混入固定背景音并复核音轨、画面尺寸、帧率、时长、字幕安全区和结尾完整性。
11. 写入日期归档和 README，只准备视频与文案，不进入任何平台、不创建发布草稿。

## 单条内容结构（行业版）

- 0—2 秒：零铺垫，第一句直接点名行业 + 抛「省钱 / 省时间 / 反差」结果（“开店做电商的，听我说：…”“做【行业】的，这个免费工具能帮你…”）。禁止“大家好”“今天介绍一个工具”。
- 2—8 秒：一句话说清这个工具在【你的行业】里替你干掉哪件烦人事、省下什么（价值前置）。
- 8 秒—主体：展开真实用法（对号入座：不懂电脑的网页版 / 会一点的一条命令 / 批量模式），优先使用官方截图、before/after 真实对比图、步骤拆解。
- 结尾：明确适合谁、不适合谁，并提出一个行业痛点互动问题（“你抠图花过多少钱？评论区聊聊”）。

目标时长 50—65 秒。标题先写行业身份 + 利益/结果，再带工具；禁止黑话（开源、Prompt、Agent、token 等 90% 的人听不懂的词）和“彻底颠覆”“又一个神器”。

## 视觉系统

沿用已确认的暖色编辑手册版式：暖米白纸张底、黑色粗线、橙红强调、酸橙绿标签和暖黄色辅助色。严禁柴主编的钴蓝演播室、深蓝电光青和蓝紫霓虹风格。

统一使用 `assets/brand/xiaochao/avatar-yellow-800.png`：

- 源文件保持 1:1，圆形容器内只允许等比例 `object-fit: cover` 居中裁切。
- 禁止分别拉伸宽高、负边距放大或使用旧卡通头像、柴犬头像。
- 头像与逐句字幕组成固定下三分之一信息条，整体放在平台底部安全区上方。
- 底部至少预留 250px 给平台信息，右侧预留操作按钮区；字幕不得贴底或被头像遮挡。

每个场景必须有一个清晰主结论和一个辅助信息区。可使用官方项目截图、流程图、步骤列表和重点数字；不得出现黑帧、空白页、字幕溢出或无意义装饰。

## 数字人 A-roll（口播，暂缓——成本考量）

> 暂缓：当前粉丝量阶段数字人 ROI 偏低，先沿用「黄色 IP 头像 + 字幕」过渡形态；等粉丝起来、有稳定变现苗头后再接入。

最终形态：A-roll 用自己的数字人出镜口播，B-roll 用工具截图/示意图，逐句字幕保留。

- **数字人工具**：硅基智能（首选，Lite ¥200/月，可克隆真人、口型同步 97%）→ 商汤如影（形象更精细，企业级偏贵）。不用腾讯智影；中文口型优先国内工具，不用 HeyGen 等海外工具。
- **形象**：选「轻度美化」的写实形象，禁止过度写实（避免恐怖谷效应，过度写实反而一眼假）。
- **克隆素材规范**（决定假不假）：4K 摄像 / 手机后置、自然光、正脸、表情丰富、无背景音乐、3–5 分钟素材；AI 训练 1–3 天。
- **口播驱动**：沿用 MiniMax 生成的同一份口播音频喂给数字人做对口型，保证 A-roll 与字幕/时长一致。
- **合规**：抖音/快手/视频号强制标注「AI 合成」，工具自带水印不得去除。
- **组合方式**：数字人 A-roll 口播段作为主画面；工具截图 / 流程图 / SVG 作为 B-roll 插入辅助信息区；逐句字幕照旧固定在平台安全区上方。
- 数字人 A-roll 接入前，先沿用现有「黄色真人 IP 头像 + 字幕」的过渡形态。

## 封面规则

每条视频生成一张「暖色编辑手册」标题卡封面（1080×1920 竖版）：暖米白纸张底、黑色粗线、橙红/酸橙绿强调，右下角用黄色真人 IP 头像 `assets/brand/xiaochao/avatar-yellow-800.png`（1:1 等比裁切）。
- 封面只放一句话钩子（同口播开头）+ 工具名，文字逐字校对，无错字、乱码、水印、平台 Logo。
- 生成后随交付包一起给，由用户发布时手动选择；不自动上传、不代选、不覆盖旧封面文件。

## 声音与背景音

配音固定显式调用 `scripts/minimax_tts.py`，不能改写共用脚本默认值：

- model：`speech-2.8-hd`
- voice_id：`Chinese (Mandarin)_Sincere_Adult`
- speed：`1.02`
- volume：`1.0`
- pitch：`-1`
- emotion：`happy`

表达像懂技术的朋友分享新发现：自然、轻微兴奋、不过度叫卖，不用新闻腔或机械匀速。

背景音固定使用 `assets/music/look-beyond.mp3`。音乐约为人声的 10%，首尾各 1 秒淡入淡出，混音目标约 `-16 LUFS`，始终以口播清晰为先。除非用户另行要求，不更换音乐。

## 每条交付物

- `videos-with-bgm/`：最终带背景音成片。
- `videos/`：无背景音 30fps 母版，并可保留渲染中间件。
- `copy/`：抖音标题、简介、话题、置顶评论，小红书标题、正文、话题和互动评论。
- 工程目录：口播分段、MiniMax 音频、来源、镜头结构、项目素材和 HyperFrames 文件。
- `qa/`：代表帧或其他质检材料。
- 当日 `README.md`：列出成片、文案、来源工程、编码和异常。

日期输出统一放在 `output/xiaochao/YYYY-MM-DD/`。同一天第二轮继续顺延期号和文件名，禁止覆盖早一轮成片。

## 生产保护

- 不自动发布，不打开抖音、小红书或其他创作者后台，不操作账号和封面。
- 不生成新封面。
- 视频、字幕、标题、简介和评论不得提及百度网盘，也不得以评论作为获取资料的条件。
- 不声称已经安装、实测或长期使用未实际操作过的工具。
- 任一关键来源、素材权利、MiniMax 配音、渲染或质检失败时，停止对应条目并写明阻塞；不得用占位内容冒充完成。
