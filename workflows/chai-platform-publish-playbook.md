# 三平台发布与恢复手册

版本：2026-10-01。依据：EP.227 实际发布与封面回查。选择器是排障线索，使用前必须读取当前页面，不能认为更新了扩展就能全自动。

## 顺序和任务记录

1. 发布包本地预检；确认用户已授权这期发布。浏览器会话由本机登录维护，包内不放账号、cookie 或连接密钥。
2. 逐平台打开实际发布页检查登录；登录失效只暂停该平台。`isLoggedIn` 可过期，不能代替实际页面。
3. 先查已有任务及作品管理页；存在同一最终视频/同一题的任务时继续原 group，不新建。自动提交保持关闭。
4. 上传视频、标题、正文、两种封面中对应的一种或两种。AI 声明、可见性、封面内容和文案均在实际页面核对；标题不能只看正文中是否出现同一句。
5. 按模板记录 `prepared → page_verified → submit_requested → platform_confirmed`。`page_verified` 须逐槽核对画面内容，尺寸相同不代表封面正确。提交前写一次 `submit_requested`；此后结果不确定时先查平台，禁止第二次点击。
6. 在同一页面提交一次，到作品管理页以作品、时间、状态和封面确认；记录“审核中/原创审核中/已发布”，不把提交成功写成公开可见。
7. 各平台分别完成；已确认提交才清理本期窗口。草稿、登录页和结果不明的任务保留，供恢复。

公开文案规则（用户 2026-10-03 更新）：三平台正文不附来源段、核验日期和网页链接；材料留内部 `sources.md`。话题按本期产品/事件与观众搜索场景独立挑选，在发布页核对实际话题；不要沿用固定的泛标签组合。事实归属和视频素材的必要标注仍按端到端流程执行。此前已发布内容不因本规则自动回改。

`publish-state-template.json` 是记录模板，**本身不提供跨进程锁或自动幂等保证**；操作者必须检查现存任务。离线预检也不授权发布。

## 本次跑通的排障路径

### 抖音

横槽先完成，竖槽最后；最后再次检查两槽，防止平台自动同步另一张图。上传文件只发一次 `change`，等真实可见的“完成”按钮可用后点击并等弹窗关闭。没有“完成”就停，不进入另一个编辑器。卡住时先关闭未保存弹窗，再在原 group 修复。

### 小红书

适配器 `div.noCover.uploadCover` 失败不等于作品已失败。EP.227 原页面通过 `.cover-edit-entry-text` 打开封面编辑器，`input[aria-label="上传封面图片"]` 上传后确认；内容声明使用真实页面控件。核对后在原页提交，再查作品管理。选择器失效时以当前 UI 为准。

### 视频号

实际页面重定向 `login.html` 时等用户登录后继续原任务。页面在 `wujie-app` shadowRoot 中；此次封面入口为 `.vertical-img-wrap .edit-btn`，上传为 `.single-cover-uploader-wrap input[type=file]`，使用该节点所属 window 的 File/Event/DataTransfer。必须完成外层确认并回看缩略图。

此次短标题字段限 16 字，逗号被拒，最终“Gemini4来了 你能用吗”可用。预检采用此次可接受的保守字符集合；未来以发布页规则为准，不以 JavaScript 写入成功证明合法。

## 结果不明时

- MultiPost failed/ready/success 均只是任务状态；查询同一作品与平台通知。
- 已看到作品审核中：记录原 ID/时间，不重发。
- 查不到且通知不明确：记录 unknown、保留原任务；不要根据等待时间编造驳回原因。
- 用户手动改过文案/封面：先回读，当前平台内容优先。

此手册和本地旧脚本的修改尚未在下一期新任务中实测；EP.227 作为操作证据，不能推定未来界面不变。
