# Jev 与同类创作者选题雷达：试采结果

时间：2026-09-28 08:32（北京时间）。目的：验证“每天看同类创作者做什么”能否补上现有 GitHub 热榜雷达的缺口，并评估 Jev 对模型 token 的实际作用。

## 结论

可以建立创作者选题雷达，但**Jev 负责低成本分类/评分或网页操作决策，不负责搜索、观看视频、创作选题**。先用平台公开搜索/API 拉取结构化元数据；把“是否同类、是实测还是罗列、对观众的任务是什么”交给规则或 Jev；只把少量候选交给编导细看。这样可能减少通用模型读取大量无关作品的 token，但需要用同一批数据做成本与准确率对照，不能只按 Jev 的单价推断总成本。

当前机器没有 `jev` 命令，也没有 `TYPESAFE_API_KEY`、`AI_GATEWAY_API_KEY` 等可用凭据。本次**未调用 Jev**。TypeSafe 官方把 Jev 定义为“输入状态，输出预定义的 Choice/Score/布尔概率”，直接 API 需要密钥；官方标示输入价格约 $0.042/百万 token，输出免费。Browser Use 的 `jev-ultrafast` 才是把 Jev 放进浏览器操作环的程序，并且示例同时要求 Jev 与文本模型密钥。来源：[TypeSafe 介绍](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[官方快速开始](https://docs.typesafe.ai/introduction/quickstart)、[Browser Use 项目](https://github.com/browser-use/jev-ultrafast)、[Vercel 当前模型页](https://vercel.com/ai-gateway/models/jev)。

抖音侧试读了现有对标账号“开源情报局”的公开主页：可见账号资料，但作品列表返回“服务异常”，关键词搜索触发登录提示，因此本轮没有取得可复算的最新抖音作品序列。仓库已有的 09-13 对标拆解可作历史样本，不能冒充今天的日更榜。`tools/douyin-viral-analysis` 的配置是 `source: mock`，也不能作为真实爆款数据源。

## 建议的每日流程

1. **固定观察名单**：先选 10–20 个同受众创作者，按平台和内容支柱分组。记录创作者、粉丝量快照、作品 URL、发布时间、标题、时长、播放/赞/藏/评、抓取时间。没有粉丝量或曝光数据时，不宣称“低粉爆款”。
2. **增量采集**：每天只抓名单里新发布作品，加少量关键词搜索补漏；URL 去重，保留原始来源。公开接口优先；页面必须点击才能读时再考虑浏览器智能体。
3. **廉价初筛**：先用代码排掉娱乐、儿童、带货等无关视频。Jev 若接入，只回答预定义问题：是否同受众、属于实测/教程/新闻/清单哪一类、是否有具体任务、是否有可验证结果。低置信度交给人。
4. **少量深看**：每天最多 5–10 条候选进入人工/通用模型拆解，提取标题承诺、前 5 秒、实证镜头、行动建议和评论里的真实需求。**只借鉴问题与表达机制，不复制脚本或封面。**
5. **回到本账号数据**：用柴主编的 5s 留存、完播、收藏和新增关注验证这些题是否适合本账号，而不是把对标账号的播放直接当答案。

## Jev 省 token 的判定法

- **最可能节省**：原本要让通用模型逐条阅读几十到几百条搜索结果、判断相关性；改为脚本初筛，Jev 对少量歧义项给 Choice/Score，只把 Top 10 的短记录交给通用模型。
- **不会节省**：平台采集、视频转录与观看、真实性核验、标题封面设计、最终编导判断。Jev 不生成解释或创意，也不能直接理解视频画面。
- **价格不等于工作流成本**：按官方 $0.042/百万输入 token，假设 95 条各送 200 输入 token，Jev 模型费约 **$0.0008**；这是纯算术示例，未计浏览器、文本模型、失败重试和集成维护，也不是本机实测账单。对 Codex 而言，收益来自“少喂无关材料”，不是 Jev 的 token 自动抵扣 Codex token。
- **先做配对测试**：同一批 100 条候选跑“规则初筛”与“规则＋Jev”两套结果；人工标注 20–30 条，比较 Top 10 相关率、遗漏的重要作品、总 token、API 费用和耗时。只有 Jev 明显提高筛选质量或降低总成本，才纳入日常流水线。

当前最值得优先做的是**确定对标创作者名单并保证能稳定取得真实作品数据**。这比先接 Jev 更决定雷达是否有用。
