## 2. 写稿与核验

```bash
mkdir -p content/episode-N/audio
# 口播：每场一个文件，5 场，首句 ≤5s 且数字/日期前置
vim content/episode-N/audio/01.txt … 05.txt
# 事实核验表（每条：断言 + 官方原文 + URL + 定性[事实]/[口径]）、六维评分、落选候选、禁项
vim content/episode-N/sources.md
# 封面文字（含每期专属装饰词 decor[]，必须是本期相关名词）
vim content/episode-N/cover-prompt.json
```

**写作纪律（每条都出过事故）**
1. **首句 ≤5 秒、数字/日期前置**（数据复盘：5 场 + 数字前置是唯一验证过有效的组合）。
2. **单一对象的专属数字必须带指代**（「第一个」「其中一家」）；**「最高 6278」这种集合属性可以，光写「6278」不行** —— EP.214/216/217/218 四期都在这条上被评审判过。
3. **「都能/都在/都要」是最危险句式**：写之前把每个对象的门槛摊开看一眼（EP.216「三个都能装」而两个要自备 API 密钥；EP.217「三个都在自己机器上跑」而 Cumora 有托管云）。
4. **许可必须回仓库 `LICENSE` 逐条核**，不能只看 GitHub API 的字段（Elastic-2.0 会报 NOASSERTION）；**三个许可能不能统称「开源」要先看一眼再写标题**。
5. **官方边界句一个字都不能省**（EP.218 把 `every merchant write` 写成「全靠人批」＝扩大范围）。
6. **「第一个/首个」类自称必须带「官方自称」**（口播 + 画面 tag + 三平台文案三处齐）。

## 3. 配音 → 时间轴 → 折行

```bash
# ③ 配音（冻结参数：male-qn-qingse / speech-2.8-hd / speed 1.08 / calm）
for i in 01 02 03 04 05; do
  python3 scripts/minimax_tts.py content/episode-N/audio/$i.txt content/episode-N/audio/$i.mp3 \
    --subtitle-output content/episode-N/audio/$i-words.json \
    --voice-id male-qn-qingse --model speech-2.8-hd --speed 1.08 --emotion calm
done

# ④ 全片时间轴
python3 scripts/build_chai_timeline.py content/episode-N
#   → publish-timeline/audio_meta.json（Σ配音、每段 duration_s + 词级时间）
#   → publish-timeline/caption_groups.json（字幕组：id/start/end/text）

# ⑤ 折行（自动生成会切词，必须人工按词边界重写）
python3 scripts/mk_line_breaks.py specs/N.json content/episode-N/publish-timeline/caption_groups.json
```

**折行硬约束**（`gen_chai_frames.py` 的渲染器有逐字硬门）
- `"".join(parts) == text` **必须完全相等**（少一个空格会被**静默**回退成单行）
- 每组 ≤2 行；**字幕带可用宽 542px ≈ 10 个中文字**，所以 ≥11 字的组必须折行
- **第二行不得以虚词（的/了/和/在/是/有…）起头**（EP.217 评审抓到的就是 `["每个同事有自己","的电脑和文件"]`）
- 自动器不懂词边界，**每次都要人工过一遍**

## 4. 规格 + 工程

```bash
# ⑤ specs/N.json：5 场字段（排版位置固定，不能换）
#   01-hook      warn_a warn_b hero_l1 hero_l2 card_big card_t card_s note
#   02-facts     repo_big repo_t repo_s st1_num st1_t st1_s st2_num st2_t st2_s tag_a tag_b note
#   03-mechanism n1_t n1_s n2_t n2_s n3_t n3_s mm mm_em tag note          （mm 需要 {em}）
#   04-action    w1_t w1_s w2_t w2_s strip strip_em note                   （strip 需要 {em}）
#   05-verdict   hero_l1 hero_l2_pre hero_l2_em hero_l2_tail card_tt card_tt_em card_ss note

# 工程：从上一期克隆（同一套版式契约）
cp -R videos/<上一期 slug> videos/<slug>
rm -rf videos/<slug>/renders videos/<slug>/assets/voice/*
# 同步音频 + 时间轴到工程
cp content/episode-N/publish-timeline/{audio_meta,caption_groups}.json videos/<slug>/
cp content/episode-N/audio/*.mp3 videos/<slug>/assets/voice/

# ⑥ 版面预检（渲染前，拦「超宽折行」这类返工）
python3 scripts/chai_layout_precheck.py specs/N.json --strict
python3 scripts/chai_script_pace.py content/episode-N            # 逐段节奏
python3 scripts/chai_density_check.py --spec specs/N.json --audio-meta content/episode-N/publish-timeline/audio_meta.json

# ⑦ 注入画面 + 字幕，再重建 index
python3 scripts/gen_chai_frames.py specs/N.json
python3 scripts/gen_chai_index.py videos/<slug> content/episode-N "<FURNITURE 如 AI DOES WORK / 218>" \
    --scenes=auto --spec specs/N.json
#   （场间 0.5s 交叉淡入淡出；加 --chapter-trans/--chapter-progress 才是长片章节形态）
```

> ⚠️ **`gen_chai_frames.py` 的 5 场角色是位置固定的**：把 facts 体放进 04 槽会当场 `KeyError`。

## 5. 渲染前门禁 → 渲染 → 装配

```bash
# ⑧ 首帧契约（常驻标准，❌=0 才渲染）
python3 scripts/chai_hook_check.py --project videos/<slug> --spec specs/N.json \
    --script content/episode-N/publish-package-YYYY-MM-DD/SCRIPT.md \
    --min-duration 25 --max-duration 60
#   ⚠️ --project 必须给 videos/<slug>；给仓库根目录会误报「缺输入」

# HyperFrames 自检（要 lint/runtime/layout/motion 全 0 error）
cd videos/<slug> && export PATH="$PWD/bin:$PATH" && npx --yes hyperframes@0.7.102 check

# ⑨ 渲染
npx --yes hyperframes@0.7.102 render        # 输出 renders/<slug>_<日期>_<时分秒>.mp4，约 1.5–5 分钟

# ⑩ 装配：+BGM（bed −9dB）+ 尾帧 1.5s；封面**不进片**
export PATH="$PWD/bin:$PATH"
python3 scripts/finalize_episode.py videos/<slug>/renders/<render>.mp4 videos/<slug>/cover.html \
    <PKG>/czbvideo-N-<slug>-bgm.mp4 --bgm --bgm-bed-db -9 --no-cover
```
- `hyperframes` 的 Google Fonts 请求偶发 `ERR_CONNECTION_RESET` → **重跑一次 check 即可**（字体已缓存）
- `bin/ffmpeg` · `bin/ffprobe` 是包装器，**必须传绝对路径**（内部会 `cd` 进 compositor 目录）

## 6. 封面（GPT 出图，独立链路）

```bash
echo N > /tmp/cover_ep.txt && rm -f /tmp/cover_only.txt /tmp/cover_no_avatar.txt
~/.local/bin/ego-browser nodejs < scripts/gen_gpt_covers.mjs
#   → content/episode-N/exp-gpt/cover-3x4.png + cover-4x3.png + cover-meta.json（generator=gpt-atutun）
#   只出某比例：echo 3x4 > /tmp/cover_only.txt
#   调试助手消息：echo 1 > /tmp/cover_debug.txt

# 安全边距（GPT 压不住 8% 硬规则，只能后处理垫底；从 _prepad 重跑不会二次加垫）
python3 scripts/fit_cover_safe_margins.py content/episode-N/exp-gpt/cover-3x4.png --scale 0.9 --mode mirror --feather 0.02
python3 scripts/fit_cover_safe_margins.py content/episode-N/exp-gpt/cover-4x3.png --scale 0.88 --mode mirror --feather 0.02
python3 scripts/chai_cover_margin.py content/episode-N/exp-gpt/cover-3x4.png     # 主标题四边 ≥8%，其他文字 ≥3%
python3 scripts/verify_cover_postprocess.py content/episode-N/exp-gpt --write-meta   # 逐像素可复算
cp content/episode-N/exp-gpt/cover-{3x4,4x3}.png content/episode-N/exp-gpt/cover-meta.json <PKG>/
```

**这条链路最近踩过的坑（都已修在脚本里）**
- ChatGPT 前端改版三次打断出图：`#prompt-textarea` 消失 → 运行时补 id；`[data-message-author-role]` 消失 → 改用 `<h4 class="sr-only">` 的「你说：/ChatGPT 说：」无障碍标题；**成图从 HTTP 地址变成 `blob:` 对象 URL** → 白名单加 `blob:` + 页面内 `fetch→FileReader` 落盘（这条曾让 30+ 轮报「候选无」，而模型其实一直在出图）
- **封面数字不要带千分位**：模型常写成 `6278`，门禁E 按 `--must "6,278"` 会失配 → 统一写「最高 6278」
- **4:3 有时会被模型塞进大段伪英文界面文字**（EP.218 首版）→ 重出该比例即可
- 安全边距不够时**从 `_prepad/` 恢复再重垫**，直接在成品上再跑一次会二次加垫

## 8. 改稿链路（顺序不可换 —— 三次事故换来的）

```
改口播/文案
  → 重录 minimax_tts（改了几句录几句）
  → build_chai_timeline.py 重建时间轴
  → **同步两个位置**：videos/<slug>/ 与 <PKG>/ 的 audio_meta.json + caption_groups.json
  → 重跑 mk_line_breaks.py（组 id 会变）→ **人工按词边界重写 line_breaks**
  → gen_chai_frames.py（重注入画面+字幕）
  → gen_chai_index.py（重建 index.html）
  → hyperframes check → render → finalize
  → 全门禁（含门禁I 回读 captions.html）
  → 重算所有文档（STORYBOARD/quality-report/...）
  → **最后** gen_package_manifest.py
```
- 「改了 A 忘了 B」已出现过四次：改 spec 没重跑 frames（EP.207）· 重录没重注入字幕（EP.209）· 改文案没重算 manifest（EP.211–213）· **重录后只同步了工程、没同步发布包（EP.216）**
- **任何 `cp` 同步前先 `diff` 确认方向** —— EP.215 就是反向覆盖，把已修好的包内 `sources.md` 覆盖回了带错字的版本，还把门禁A 的 L1 打到 0.94

## 9. 独立评审（发布前的最后一道）

```bash
# 派一个**未参与制作**的 subagent，给它：包路径 + 首轮条目清单 + 可用工具清单 + 纪律清单
# 首轮：全量（事实/许可/口径/禁项/门禁复跑/抽帧 OCR/三平台文案）
```

- **P0 定义**：会导致事实错误 / 误导 / 违规 / 发布事故，**P0=0 才能发**
- 评审必须**自己执行**命令取证；报告里不许出现没跑过的检查
- 实测约三分之一发现是误报（模型把黄绿读成橙色、「口径」读成「口令」、把官方仓库名当错字），**要逐条甄别后再采纳**，但**误报不等于可以不看**

**发布期的三个已知坑**
1. **视频号登录态会静默过期**：状态卡在 `publishing/filling`，而 `get_account` 仍报 `isLoggedIn: true`（旧读数）。

**事故**：另一个并行会话在取期号时按「`content/` 里最大期号 + 1」推算，**误把已经在用的 `episode-219` 当空号**（那期 08:38 就开工、18:35 完成，只因为目录 mtime 看起来早），

**取期号三步（缺一不可）**：
```bash
# ① 全量列一遍，别只看最大号
ls -d content/episode-* | sort -V | tail -10
ls specs/ | grep -E '^[0-9]+\.json$' | sort -V | tail -10
# ② 看 git 里哪些期还是「未跟踪」——未跟踪 ≠ 没在用，只说明还没提交
git status --porcelain content/ | grep episode- | head
# ③ 开写前确认目标目录「不存在或确实为空」，并在同一条命令里把它占住
[ -e content/episode-N ] && echo "❌ $N 已被占用" || { mkdir -p content/episode-N/audio; echo "✅ 占用 $N"; }
```
**并行会话场景**：只要你可能不是唯一在写这个仓库的人，期号就必须**先占后用**；
更稳的做法是在仓库根维护一个 `content/.episode-lock`（每行一个在用期号），开工前追加、收工后保留。

**写坏了的止损顺序**：① 立刻停写目标期；② `ls -la` 逐文件看 mtime，分清哪些是原件、哪些是自己刚写的；
③ 从**同期的其它落点**恢复（发布包里的 `audio_meta.json`/`caption_groups.json` 含完整时间轴与逐词文本；工程目录 `videos/<slug>/assets/voice/*.mp3` 含原始配音；`publish-copy.md`/`quality-report.md`/`STORYBOARD.md` 含口径与主张）；
④ 恢复不了的文件**必须在文件头显式写「本文件被误覆盖，此为按 X/Y/Z 重建」**，并留一份事故说明。
